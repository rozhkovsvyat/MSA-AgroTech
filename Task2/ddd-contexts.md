# Доменные контексты

Одинаковы для А и Б; меняется размещение, но правила обработки опасностей и команд сохраняются.

| Контекст | Владение и правила | Контракт / связь |
|---|---|---|
| Наблюдение | Кадры, версия модели, признаки, observation_id | Общий формат наблюдения ObservationRecorded (Published Language); адаптеры камер и модели |
| Инциденты | Зона, окно 60 с, подрепорты, один ответственный, исход | Получает наблюдения от поставщика данных (Customer/Supplier); задаёт эскалацию оповещению |
| Оповещение | Попытки и подтверждения каждого получателя | Б: независимый потребитель Kafka; ACK устройства не принятие человеком |
| Оборудование | Лимиты, допуск на ферме, command_id и неизвестный исход | Адаптеры переводят протоколы поставщиков в наш формат (Anti-Corruption Layer) |
| Учёт | Подтверждённое поголовье и остатки кормов | Наблюдения не меняют учёт без правила / корректировки |
| Аналитика | Прогнозы потребления, базовые и пользовательские метрики | Строит данные для отчётов из событий учёта и показаний оборудования |
| ИИ-триаж | Рекомендации с версией модели и доказательствами | Анализ асинхронно; команды через тот же доменный API |
| Клиенты и доступ | Tenant, фермы, права, сроки, регистрация | Общий API подключения клиентов и правил доступа (Open Host Service) |
| Биллинг | Тариф, объём использования, счёт, платёж, квота | Получает события использования и рассчитывает оплату |

Между наблюдением и инцидентами нет общей транзакции. В Б оповещение читает первое наблюдение из Kafka, не ждёт записи основной карточки сервисом инцидентов; в А используется прямая доставка. Терминал группирует локальную карточку, затем связывает её с основной карточкой по observation_id. В А часть контекстов — модули одного приложения; в Б — отдельные процессы. Kafka и PostgreSQL не являются бизнес-контекстами.
