# Контракты интеграций

| Связь | Семантика и технология | Причина / отказ |
|---|---|---|
| Камера → видеоаналитика | RTSP, camera_id, время кадра | Совместимость камер; reconnect и мониторинг свежести, не ping |
| Видеоаналитика → терминал | Наблюдение, HTTPS/mTLS, постоянный observation_id | Тревога без ожидания журнала; локальная дедупликация |
| Видеоаналитика → сигнализация | ID и зона через локальный адаптер | Параллельный канал; отдельное питание и трасса по deployment-плану |
| Видеоаналитика → журнал | А: SQL; Б: Kafka/TLS, ключ farm+camera | История и независимые потребители; буфер повторов |
| Терминал → доменный API | HTTPS, token, idempotency key | Синхронный ответ «зафиксировано / неизвестно / отказ», без выдуманного успеха |
| Инциденты → журнал / UI | Факты с aggregate_version / SSE | Один сериализованный writer по ключу; терминал согласует локальные карточки |
| API → IdP | OIDC при входе, HTTPS/JWKS | Проверка access token в API; неизвестный ключ не принимается |
| Центр → ферма | Версионированные политики, TTL, подпись, отдельный топик | Офлайн-права до срока; отзыв по WAN не мгновенный |
| Ферма ↔ центр | Б: MM2/Kafka, А: outbox/HTTPS | Асинхронность; P02 измеряется end-to-end, а не одним lag брокера |
| Управление → шлюз | HTTPS, command_id, expires_at, epoch | Окончательный допуск локален; просрочка и старый владелец отсечены |
| Шлюз ↔ устройство | MQTT / OPC UA / Modbus через адаптер | Фактический протокол определяется производителем; потерянный ответ → unknown |
| Ферма → медиасервис | HTTPS/S3, хеш, tenant/farm, ссылки | Видео не проходит через Kafka; ограниченная очередь и повтор |
| Kafka → проекции / ИИ | События, версия схемы, cursor, event_id | Повторы допустимы; несовместимый формат в quarantine с тревогой мониторинга |
| Интеграции ↔ ERP/BI | HTTPS API, versioned DTO | ACL защищает модель от чужих справочников; отчёты не пишут доменные таблицы |

Команды, события и снимки имеют разные топики и схемы. Повтор события сохраняет ID, replay не запускает оборудование, платежи или старые первоначальные тревоги. Канонические инциденты группируются по зоне; порядок команд держится по ключу агрегата. Позиция Kafka не заменяет проверку бизнес-версии.
