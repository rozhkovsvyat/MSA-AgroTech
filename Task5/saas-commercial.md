# Коммерческая модель и эксплуатация SaaS

## Подписки

| Тариф | Возможности | Единица |
|---|---|---|
| Пилот | 1–3 фермы, базовые отчёты | Ферма / месяц |
| Производственный | Пользовательские метрики, API, ИИ-триаж | Ферма + сверхлимитное использование |
| Корпоративный | Выделенные ресурсы или экземпляр, договорный SLA | Индивидуальный расчёт |

Цены не назначены: нужны данные затрат. Тариф не выключает локальную защиту животных. Неоплата ограничивает новые подключения и облачные квоты после предупреждения; завершение обслуживания включает экспорт и подтверждённое удаление по регламенту.

## Учёт использования и оплата

Центральная Kafka передаёт события использования ресурсов с tenant_id, farm_id, event_id, единицей, периодом и версией тарифа. Биллинг подавляет повторы по event_id и ведёт свой журнал счетов. Счёт содержит снимок тарифа; поздние события после WAN-обрыва дают корректировку, не второе списание за тот же факт. Метрики: активные фермы/камеры, API-вызовы, объём медиа, ресурсы ИИ. Пользовательские производственные метрики хранят единицы, формулу и версию отдельно от платёжных.

Учебный выбор российского провайдера — **ЮKassa**. При создании платежа передаётся ключ защиты от повторного выполнения (idempotency key); отсутствие ответа не означает отказ платежа. Уведомление провайдера (webhook) служит сигналом проверить состояние платежа по API; повтор не создаёт новый платёж. Секреты и платёжные данные не хранятся в клиентском интерфейсе. Возможность конкретного договора и автоплатежей проверяют при внедрении. [Документация платежей](https://yookassa.ru/developers/api#create_payment).

## API и самообслуживание

Разрешения API (scope): `incidents:read`, `metrics:read`, `media:read`, `equipment:request`. Tenant и farm берутся из проверенного контекста; команда всё равно проходит локальный допуск. Подписанный токен доступа (JWT) имеет короткий срок действия; центральный список отозванных токенов и версия прав ускоряют отзыв, при отсутствии проверки отзыв действует по сроку токена. На ферме — срок офлайн-прав, без обещания мгновенного отзыва через оборванный WAN.

Портал разработчика содержит описание API (OpenAPI), примеры, журнал версий, тестовую среду с отдельной компанией и управление ключами доступа приложений. Панель самообслуживания: организация, пользователи, фермы, тариф, счета, usage и экспорт. Отдельная панель администратора платформы не вводится; служебные операции идут через регламентированные служебные задачи и API.

## Масштабирование и изоляция

Нагрузку API и фоновых обработчиков распределяют между дополнительными экземплярами; партиции выбираются по tenant/farm/агрегату с контролем горячих ключей. БД распределяются по серверам через реестр; перенос включает копию, догоняющую синхронизацию, переключение версии реестра и проверку. Квоты, ограничения подключений к БД и фоновых задач не позволяют одному клиенту занять все общие ресурсы. Права на топики Kafka, доступ к файлам клиента и разрешения API проверяются отдельно от доступа к БД. Фермы автономны, добавление новой не требует релиза остальных.
