# Сценарии проверки

| Различающая пара | Ожидание |
|---|---|
| Все узлы / любые два вычислителя выключены | Б сохраняет хотя бы одну обработку каждой из 16 камер; А при потере сервера — нет |
| Kafka доступна / ISR ниже minISR | В Б сигнал доставляется только при доступной записи/чтении; при ISR<2 новые сигналы ожидают доставки, после восстановления доставляются с отметкой задержки |
| Терминал доступен / отключён | Сирена работает при отдельной исправной трассе; полноценная карточка без терминала не обещана |
| ИИ доступен / выключен | Тревога одинаково немедленная; рекомендация только в первом случае |
| Один observation_id повторён / новый ID | Повтор не новый подрепорт; новый сохраняет источник и доказательства |
| Камера отвечает ping / выдаёт свежие кадры и результат | Только второе подтверждает восстановление наблюдения |
| Команда истекла / ещё действует | Первая не исполняется; вторая проходит все локальные проверки |
| Старый epoch / новый epoch | Первый отклонён шлюзом, второй проверяется по лимитам и сроку |
| Tenant A / запрос A к данным B | Свои данные доступны; чужие отвергаются на API, БД, событиях, медиа |

В пакете реально исполняются проверки размещения, арифметики, ссылок и рендера. Остальные строки — программа испытаний реализации. Нельзя из логической модели получить измеренные 5 секунд или 99,95%.

Дополнительные пары для Б:

- RF=3/minISR=2 / RF=4/minISR=2: перебрать назначения реплик и десять пар отказов из полностью синхронного состояния; второй вариант сохраняет минимум две ISR. Проверить служебные топики и резерв потребителей.
- Kafka восстановлена: без подавления задержанный случай оповещается; с подтверждённым подавлением за период — только сохраняется. Свежий случай вне периода оповещается в обоих режимах. Пересборка представления сама не включает сирену.
- Терминал выключен / сирена выключена: независимые группы не блокируют исправного получателя.
- Обычная нагрузка / два узла выключены плюс догонка реплик: замерить весь P01, включая лидера и rebalance. Превышение пяти секунд — провал приёмки, не разрешённое исключение.
- ACK Kafka / подтверждённый сигнал: первое не выдаётся за второе; контролируется недоставка и возраст очереди.
- Локальный адресат / адресат вне ЛВС при WAN-обрыве: WSS доступен только локальному, удалённая доставка ожидает восстановления связи.

- Две ISR / одна ISR: при minISR=2 первая конфигурация пишет, вторая — нет; при minISR=3 обе остановились бы.
- Две подтверждённые копии / обе потеряны: показать предел сохранности записи в деградации.
- Ответ сирены получен / потерян: повтор команды не перезапускает звук; старая версия не отменяет выключение; исчерпание повторов видно оператору.
- Поздняя неоднозначная связь: агент предложил / недоступен — отдельная тревога в обоих случаях; объединение только после подтверждения человека.
- Streamiz-процесс перезапущен с прежним томом / задача перенесена на другой узел: проверить полноту состояния по changelog, время догонки и отсутствие повторных внешних действий.

## Пилот до закупки

Сначала предварительная проверка в облаке, затем один вычислитель целевого класса с десятью независимыми цепочками декодирования и распознавания плюс Kafka и фоновые сервисы. Один поток камеры можно подать десять раз для начального нагрузочного теста; результат не заменяет разные сцены, разрешения, движение и освещение. Проверить, что конвейеры действительно выполняются независимо, без общего закэшированного результата.

Далее арендовать дополнительные одинаковые узлы, вплоть до пяти, если позволяет бюджет. На полном стенде проверить все десять пар отказов, баланс разделов, неполный ISR, восстановление состояния и задержку от кадра до получателей. Два узла полезны для промежуточной проверки сети, но не доказывают работу кворума из пяти. При провале нагрузки менять железо/модель и повторять измерения до закупки.
