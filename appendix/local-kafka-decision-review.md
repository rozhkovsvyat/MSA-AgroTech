# Границы гарантии локальной Kafka

[ADR 003](../ADR/003-local-kafka.md): пять брокеров и контроллеров, RF=4/minISR=2, acks=all, unclean election выключен. Четыре реплики каждой партиции находятся на разных устройствах. Политика распространяется на события, состояние, позиции и транзакции.

| Исходное состояние / отказ | Результат |
|---|---|
| Четыре реплики синхронны, отказали любые два узла | Минимум две ISR остаются; управление сохраняет три контроллера; запись возобновляется после переключения |
| До отказов одна реплика отставала, потеряны две из трёх актуальных | Одна ISR; запись останавливается, хотя устройств в сети может быть три |
| Новая запись подтверждена только двумя ISR, затем потеряны обе | Сохранность этой записи не гарантируется |
| ISR<2 или Kafka недоступна | Новые тревоги ожидают доставки; ручной режим на ферме, без обхода Kafka |
| WAN недоступен, локальный кластер исправен | Местная тревога работает; обмен с центром отстаёт |

Исполнимая модель перебирает все назначения четырёх реплик по пяти узлам и все десять пар отказов. RF=3/minISR=2 имеет отрицательные случаи; RF=4/minISR=2 выдерживает каждую пару из полного ISR. RF=5/minISR=2 имеет дополнительный запас на отставание ещё одной копии после двух отказов. При двух ISR minISR=2 разрешает запись, minISR=3 запрещает: это сознательный выбор доступности, не случайное следствие числа устройств.

Пример неполного ISR: копии партиции на E1–E4, E5 её не хранит. После отказа E1/E2 остаются E3/E4/E5, но журнал этой партиции есть лишь на E3/E4. Если E3 отстаёт, одна актуальная копия не разрешает запись. Контроллер на E3 при этом может продолжать работать: отставание данных не равно потере всего устройства. Это дополнительная деградация сверх двух отказов.

Расчёт не моделирует задержку, протокол Kafka, сбой питания или дисковый flush. Три обработки одной камеры на разных узлах не заменяют реплики одного события. Для каждого канала проверяются служебные топики, состояние потребителей и резерв процессов.

История нужна для разбора обнаружения и реакции, команд оборудования, аналитики и восстановления состояния. Учебный горизонт автономности — 7 суток, хранение событий на ферме минимум 30 суток, центральный архив — год. Ёмкость: поток событий × горизонт × RF плюс запас; медиа отдельно. RF=4 экономит 20% места для реплик относительно RF=5, а не 20% всей инфраструктуры. Очистка требует подтверждённой внешней копии и истечения срока; заполнение диска может остановить тревоги.

Первоисточники: [KRaft](https://kafka.apache.org/41/operations/kraft/), [acks](https://kafka.apache.org/41/configuration/producer-configs/#acks). Проверено 29.09.2026.
