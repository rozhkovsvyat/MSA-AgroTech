# Безопасная команда оборудованию

Конверт: command_id, tenant_id, farm_id, device_id, operation, quantity/unit, issued_at, expires_at, expected_version, actor, authority, epoch. Команда и событие результата различаются.

Финальный допуск — на ферме: права, срок, лимиты, свежесть данных и отсутствие невыясненной конфликтующей операции. Запись допуска должна быть устойчивой до физической отправки. При недоступном журнале новое действие не считается разрешённым.

Потерянный ответ означает unknown. Сначала автоматический запрос состояния/проверка фактической выдачи; затем уполномоченный сотрудник, если неопределённость не снята. Сотрудник не получает подразумеваемого обхода лимитов. Частичная выдача завершает эту команду фактическим количеством; остаток — отдельная команда. Просрочка не запускает оборудование; новая команда возможна после оценки актуальной потребности по правилам.

Повтор транспортного сообщения сохраняет command_id. Одной записи ID в нашем сервисе недостаточно: шлюз/исполнитель должен сохранять дедупликацию на стороне физического эффекта либо достоверно проверять исход. Для failover нужен монотонный epoch и lease в исполнителе/шлюзе. При недоступном реестре допуска или неподдерживаемом fencing автоматический запуск на резерве запрещён. Replay не исполняет историю.
