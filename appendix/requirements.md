# AgroWatch: требования и критерии проверки

Источник: [полное задание курса](https://practicum.yandex.ru/learn/microservice-architecture/courses/c116d4da-efaa-499d-80e5-59f9f644a2dc/sprints/1023015/topics/ba18586d-5938-4902-9237-d0d516dd372f/lessons/6ce6968f-4bf2-45b3-b35a-f88ea15e9c78/), Идентификаторы F01–C05 используются для ссылок из ADR.

## Бизнес и ограничения

Пилот на нескольких свинофермах AgroTech X, затем распространение на остальные. Указанные в задании 150 тепличных комплексов не определяют число свиноферм и камер пилота. Цель — уменьшать ущерб и повышать эффективность наблюдения. SaaS-проектирование обязательно в расширенном Task5, хотя реализация SaaS для пилота не требуется.

|---|---|---|---|
| F01 | Обнаруживать беспокойство, драки и придавливание поросят; оповещать дежурного. | Видеоаналитика и оповещение | Проследить путь от опасности в кадре до сигнала дежурному. |
| F02 | Выявлять признаки болезни и гибели по внешности и поведению животных. | Видеоаналитика и инциденты | Показать категории наблюдений, версию модели и проверку сотрудником. |
| F03 | Управлять кормушками и поилками разных производителей. | Шлюз оборудования | Показать выдачу команды, подтверждение исполнения и действия при потере ответа. |
| F04 | Следить за состоянием систем фильтрации воды. | Телеметрия и правила | Показать получение показателя, обнаружение отклонения и местное оповещение. |
| F05 | Подсчитывать поголовье. | Учёт и видеоаналитика | Объяснить, как учитываются повторные наблюдения, тени и ручные корректировки. |

| F08 | Предоставлять API для веб- и мобильных приложений. | API и пользовательские приложения | Показать запросы локального терминала и центрального кабинета. |

| P03 | Обрабатывать видео в реальном времени; в задании указаны миллисекунды без точного предела. | Видеоаналитика | До испытаний согласовать разрешение, частоту кадров и допустимую задержку. |
| R02 | Обеспечить целевую доступность 99,95%. | Размещение и восстановление | Согласовать измеряемые функции и период расчёта. Проверить отказы и время восстановления; число узлов само по себе не доказывает доступность. |

| C02 | Использовать готовую модель распознавания от партнёров. | Адаптер модели | Проверить совместимость модели с оборудованием и возможность смены версии. |
| C03 | Поддерживать камеры разных производителей; учитывать ночь, слепые зоны и искажения объектива «рыбий глаз». | Видеозахват и сеть | Проверить покрытие зон и качество распознавания в этих условиях. |
| C04 | Предусмотреть альтернативу нестабильному Wi-Fi на ферме. | Сеть фермы | Показать проводные соединения и поведение при потере связи камеры или вычислителя. |
| C05 | Учитывать ложный подсчёт теней и сложность отслеживания похожих животных; для MVP идеальная точность не требуется. | Учёт и ограничения модели | Не обещать безошибочную идентификацию; предусмотреть проверку и корректировку результатов. |

## AS-IS: что уже есть

Схема задания содержит React web, Flutter mobile, ERP 1C Agro; тепличные SCADA Ignition, автополив C++, сенсоры Python; Kafka, Node-RED, TimescaleDB, Java-трекинг; планирование Kotlin, топливо Go, диагностику C#; MinIO, ClickHouse, Spark Python и Power BI. На связях указаны MQTT, OPC UA, Modbus TCP, LoRaWAN, REST, Kafka Connect/S3 и Airflow ETL.

Это исходный ландшафт, а не обязательный список новых технологий. Существующий Kafka в центре — кандидат для интеграции. Из его наличия не следует необходимость Kafka на каждой ферме или прямого доступа мобильного клиента к брокеру. Выбор интеграций обоснован в ADR 006.

## Что требуется сдать

| Каталог | Артефакты | Приёмка |
|---|---|---|
| Task1 | Два C1 + ADR с проблемой, контекстом и компромиссами | Две жизнеспособные альтернативы; стек и команды на этом этапе не требуются |
| Task2 | Контексты DDD, два C2, ADR интеграций | У каждой связи семантика и мотив выбора технологии; риски обоих вариантов |
| Task3 | C3 и C4 обоих вариантов | Понятна выбранная область детализации и связь с C2; одинаковая глубина сравнения |
| Task4 | ADR критериев, анализа и рекомендации | Одинаковые критерии, реальные компромиссы, обоснованная рекомендация |
| Task5 | Новый ADR со ссылкой на Task4; 2–3 модели изоляции с C2 (C3 при необходимости); итоговые C1+C2; C2 AgroTech как клиента с фермами | Тарифы/подписки, биллинг, российская платёжная система, API scope, dev-портал/документация, самообслуживание, горизонтальное масштабирование, метрики использования, изоляция |

Для Task5 сравниваются схема БД, отдельная БД, отдельный инстанс. Специальный административный интерфейс пока не предполагается; панель самообслуживания клиента всё равно нужна.


## Неизвестные параметры

Число ферм/камер/потоков, FPS и разрешение, доступный edge/GPU, максимальная длительность автономности и объём буфера, критерий доступности 99,95%, допустимая деградация при отказе единственного сервера, RTO/RPO, срок хранения видео, требования к персональным данным, точность модели и пороги ложных тревог. Для учебного проекта допускаются явно отмеченные допущения; их не выдаём за данные заказчика.
