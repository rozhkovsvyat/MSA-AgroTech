# Локальный доступ и исходные пороги

Окончательный допуск оборудования — на ферме. Центр отправляет намерение, а не обходит лимиты. Обычные офлайн-права ограничены сроком. Местный ответственный с отдельным полномочием может предоставить ограниченный аварийный доступ с аудитом. Право управления оборудованием само по себе не даёт права выдавать доступ.

| Параметр | Начальная точка | Условие |
|---|---|---|
| Группировка | 60 с | Принятое правило; не задерживает тревогу |
| Основной → резервный | 2 мин от открытия без принятия | Учебный baseline |
| → руководитель | 5 мин от открытия без принятия | Учебный baseline |
| Контроль результата | 15 мин критичный / 60 мин обычный после принятия | Контроль, не разрешение ждать перед спасением |
| Офлайн-права | 8 ч с момента выдачи | Не продлеваются перезапуском |
| Срок команды | 5 мин с issued_at | Проверяется до исполнения; не срок аварийного реагирования |

Версии политик подписаны и доставляются заранее, JWKS кэшируются; неизвестный ключ и истёкшие права отклоняются. Отзыв из центра при отсутствии связи нельзя считать полученным. Автоматическая тревога независима от входа пользователя. Пороги калибруются на пилоте, бюджет P01 из задания не увеличивается.


Офлайн-права — отдельный подписанный **offline grant**, а не продлённый облачный access token. Поля: subject, tenant, farm, device/session binding, действия и лимиты, issued_at, expires_at (до 8 ч), policy_version, issuer. Локальный API проверяет подпись по доверенным заранее полученным ключам, срок и привязку к ранее аутентифицированной локальной сессии/устройству. Облачный JWT с коротким TTL используется только для онлайн-API. Чужая ферма, устройство, неизвестный ключ или истёкший grant дают отказ. Местный аварийный доступ имеет отдельного уполномоченного выдающего и аудит.

Таймер первоначальной эскалации ведёт **локальный агент терминала** от первого received_at, не ожидая канонического инцидента в Kafka. Он хранит сроки и локальный факт принятия; 2/5 минут запускают локальный push зарегистрированным устройствам резервного дежурного/руководителя в ЛВС и повторную сигнализацию через тот же адаптер. При WAN-обрыве адресат вне ЛВС недоступен: сообщение остаётся pending, локальная повторная тревога сохраняется. При отказе самого терминала таймеры и подробная маршрутизация деградируют; независимая первичная сирена остаётся. Это граница выбранной пары получателей, а не обещание полной независимости всех эскалаций. После восстановления журнала временные локальные действия согласуются по ID и версии; UI не выдаёт их за уже зафиксированное каноническое состояние.

Локальные мобильные получатели держат WSS-соединение с агентом терминала по ЛВС; это не облачный push. Устройства дежурных должны поддерживать приём в фоне (управляемый режим или постоянный экран), что проверяется на пилоте. Без этого подтверждение доставки не считается полученным, повторная местная сигнализация сохраняется.
